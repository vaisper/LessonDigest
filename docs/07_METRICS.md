# 07 — Metrics: метрики и эксперименты

## 1. Зачем метрики

Без метрик проект = «красивая демо».  
С метриками = инженерное исследование: гипотеза → эксперимент → вывод.

## 2. Метрики MVP0 (обязательные)

### 2.1 Полезность дайджеста (human)
- Шкала **1–5** от ученика: «насколько конспект помог бы подготовиться / вспомнить урок».  
- Цель: **среднее ≥ 3.5** на ≥ 5 записях.

### 2.2 Домашнее задание
- Бинарно: выделено **корректно / нет / не было домашки**.  
- Цель: **≥ 70%** корректных на записях, где домашка реально звучала.

### 2.3 Технические
- `asr_sec`, `llm_sec`, `total_sec`  
- `duration_sec` аудио  
- realtime factor: `asr_sec / duration_sec` (чем меньше, тем лучше)  
- длина транскрипта / дайджеста  

## 3. Метрики поздних фаз (исследовательские)

| Метрика | Смысл | Как |
|---------|--------|-----|
| WER | качество ASR vs ручная расшифровка куска | вручную 2–3 мин эталона |
| ROUGE / overlap | близость к «эталонному конспекту» | эталон пишет человек |
| Homework F1 | precision/recall маркеров домашки | разметка |
| Сравнение LLM | GigaChat vs YandexGPT | один и тот же transcript |
| Своя математика vs LLM | TextRank vs LLM key points | qualitative + overlap |

## 4. План эксперимента MVP0

1. Собрать **5–10** аудио по 10–20 минут (согласие!). Альтернатива: открытые лекции.  
2. Прогнать единым промптом `v1`.  
3. Каждый дайджест оценить по форме:

```text
run_id:
usefulness_1_5:
homework_correct: yes/no/n/a
comments:
```

4. Свести таблицу в `digests/_eval/summary.md`.  
5. Выводы: что ломается (шум, формулы устно, домашка в конце очень тихо).

## 5. Антинаучные ловушки

- Не оценивать только на идеальной студийной записи.  
- Не менять промпт между прогонами «молча» — только через `prompt_version`.  
- Не считать успехом «LLM ответила красиво», если домашка выдумана.

## 6. Критерий «MVP0 сдан»

- Пайплайн воспроизводим на новой записи одной командой.  
- Есть ≥ 5 оценённых прогонов.  
- Средняя полезность ≥ 3.5 **или** честный разбор, почему нет, и план фикса.  
- Документированы ограничения.
