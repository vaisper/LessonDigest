# 14 — Analytic: своя текстовая аналитика (TF-IDF + TextRank)

## 1. Зачем

GigaChat — внешняя модель. Чтобы проект не сводился к «обёртке над API»,
в системе есть **собственный** модуль анализа текста, не использующий нейросети:
он извлекает ключевые термины, ключевые предложения и домашку прямо из транскрипта,
а затем сравнивается с дайджестом LLM по метрикам.

Это отвечает на вопрос «где тут твоя математика» и даёт измеримую исследовательскую часть.

## 2. Метод

### 2.1 Препроцессинг

- разбиение на предложения — `razdel.sentenize`;
- токенизация — `razdel.tokenize`;
- лемматизация — `pymorphy3` (нормальная форма слова);
- фильтрация стоп-слов (`analytic/data/stopwords_ru.txt`) и коротких/служебных токенов.

### 2.2 Ключевые термины — TF-IDF

`sklearn.feature_extraction.text.TfidfVectorizer`:

- документы = предложения урока;
- признаки = отдельные леммы и биграммы (`ngram_range=(1,2)`), поэтому находятся
  и «дискриминант», и «теорема виета»;
- вес термина = сумма TF-IDF по предложениям; берём top-K.

`IDF` считается по предложениям урока (при желании можно подключить фоновый корпус
из прошлых транскриптов).

### 2.3 Ключевые предложения — TextRank

- строим TF-IDF-векторы предложений, считаем косинусную близость;
- строим граф (узлы — предложения, рёбра — близость выше порога);
- `pagerank` (networkx) ранжирует предложения;
- берём top-N и возвращаем их в исходном порядке урока.

Это **extractive**-подход: предложения берутся дословно, поэтому метод не может
выдумать факт.

### 2.4 Детектор домашки

Регулярные маркеры (`домашн`, `на дом`, `парагр`, `§`, `упражнени`, `задани`, `задач`,
`номер`, `№`, `подготов`, `выучить`, `повторить`) с приоритетами. Берётся предложение
с наивысшей уверенностью, при равенстве — **последнее** (домашку задают в конце).

## 3. Метрики сравнения с LLM (`analytic/compare.py`)

- `terms_precision` — доля наших top-терминов, которые встречаются в концепциях LLM;
- `terms_recall` — доля концепций LLM, содержащих хотя бы один наш термин;
- `terms_f1` — их гармоническое среднее;
- `sentences_precision/recall/f1` — то же для предложений против `key_points`
  (совпадение по Jaccard ≥ 0.25);
- `homework_grounded` — доля чисел из домашки дайджеста, реально встречающихся
  в транскрипте (простой детектор выдуманных номеров);
- `formulas_grounded` — то же для чисел в формулах.

## 4. Интерфейс

Артефакты:

- `transcripts/{run_id}.analytic.json` — машинный результат;
- `digests/{run_id}.analytic.md` — человекочитаемый вид.

CLI:

```powershell
lessondigest analyze --run 20260923_algebra_a1b2c3
lessondigest analyze --run 20260923_algebra_a1b2c3 --compare
```

В пайплайне этап `analytic` выполняется автоматически после ASR, если в `config.yaml`
включено `analytic.enabled: true`. Метрики сравнения дописываются в
`runs/{run_id}/metrics.json` в секцию `analytic_compare`.

## 5. Конфигурация

```yaml
analytic:
  enabled: true
  top_terms: 12
  top_sentences: 7
  min_sentence_chars: 40
  ngram_max: 2
```

## 6. Зависимости

`scikit-learn`, `razdel`, `pymorphy3`, `pymorphy3-dicts-ru`, `networkx`
(extra `analytic`: `pip install "lessondigest[analytic]"`).

## 7. Ограничения

- Качество зависит от лемматизации и от шума ASR (см. `13_RISKS.md`, R13).
- Extractive-предложения дословны, поэтому слабо пересекаются с пересказом LLM —
  низкий `sentences_f1` у «пересказных» дайджестов это ожидаемое поведение, а не ошибка.
- `homework_grounded` по числам может занижать оценку, если LLM записала число цифрами,
  а в транскрипте оно произнесено словами («пятый» → «5»).
