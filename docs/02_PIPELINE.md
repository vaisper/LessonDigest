# 02 — Pipeline: пайплайн обработки

## 1. Обзор

Один **Run** = обработка одного аудиоурока от входа до дайджеста.

```text
RUN_ID = {date}_{subject}_{short_hash}
например: 20260923_algebra_a1b2
```

Каждый этап идемпотентен по возможности: повторный запуск с тем же `RUN_ID` перезаписывает или пропускает готовые артефакты (флаг `--force`).

## 2. Этапы (детально)

### Stage 0 — Plan / Validate

**Вход:** путь к аудио, опции CLI.  
**Выход:** `meta/run.json` (создан), валидный run context.

Проверки:
- файл существует, размер > 0;
- расширение в whitelist: `.m4a`, `.mp3`, `.wav`, `.ogg`, `.flac`;
- длительность (через ffprobe) — предупреждение если > 60 мин;
- наличие ключей API (если нужен облачный шаг);
- свободное место на диске.

### Stage 1 — Ingest

**Вход:** произвольный путь к аудио.  
**Выход:** каноническая копия в `audio/raw/{RUN_ID}.{ext}` + запись в meta.

Действия:
- скопировать файл в проект (не трогать оригинал на телефоне);
- посчитать checksum (SHA-256);
- извлечь duration, sample rate, channels (ffprobe);
- нормализовать имя.

Опционально Stage 1b — **Normalize audio**:
- конвертация в mono 16 kHz WAV для ASR (`audio/normalized/{RUN_ID}.wav`);
- лёгкий denoise — только если доказано улучшение WER (не в MVP0 обязательно).

### Stage 2 — ASR (Speech → Text)

**Вход:** `audio/normalized/...` или raw.  
**Выход:**
- `transcripts/{RUN_ID}.txt` — чистый текст;
- `transcripts/{RUN_ID}.segments.json` — сегменты с таймкодами (если провайдер даёт);
- обновление meta: model, device (cpu/cuda), elapsed_sec, char_count, language.

Алгоритм:
1. Выбрать provider (`whisper_local` | `yandex_speechkit` | …).  
2. Транскрибировать.  
3. Постобработка текста (лёгкая): схлопнуть пробелы, сохранить пунктуацию модели.  
4. **Не** вычищать содержание агрессивно — LLM должна видеть исходник.

Ошибки:
- OOM → предложить меньшую модель Whisper;
- API timeout → retry с backoff;
- пустой текст → fail run.

### Stage 3 — Chunk (если нужно)

**Зачем:** длинный транскрипт не влезает в контекст или качество суммаризации падает.

**Вход:** полный текст.  
**Выход:** `transcripts/{RUN_ID}.chunks.json`.

Стратегия MVP0:
- если `tokens_est < CONTEXT_SOFT_LIMIT` → один чанк;  
- иначе: резать по паузам/сегментам ~8–12 мин аудио эквивалента, overlap 1–2 предложения.

Оценка токенов (грубо для русского): `chars / 2` … `chars / 3` — калибровать эмпирически.

### Stage 3b — Analytic (своя аналитика, TF-IDF + TextRank)

**Вход:** транскрипт.  
**Выход:** `transcripts/{RUN_ID}.analytic.json` + `digests/{RUN_ID}.analytic.md`.

Без нейросетей: TF-IDF даёт ключевые термины, TextRank — ключевые предложения,
regex — кандидатов домашки. Включается флагом `analytic.enabled`. После суммаризации
в `metrics.json` дописывается секция `analytic_compare` (сравнение с дайджестом LLM).
Подробно — `14_ANALYTIC.md`, результаты — `15_ANALYTIC_RESULTS.md`.

### Stage 4 — Summarize (LLM)

**Вход:** текст или список чанков.  
**Выход:**
- `digests/{RUN_ID}.md` — человекочитаемый дайджест;
- `digests/{RUN_ID}.json` — структурированные поля (для метрик и интерфейсов);
- meta: model, prompt_version, tokens_in/out, elapsed.

Режимы:

**A. Single-shot (MVP0 default)**  
Один промпт на весь транскрипт.

**B. Map-Reduce (длинные уроки)**  
1. Map: краткое резюме каждого чанка (тот же schema).  
2. Reduce: слить резюме в финальный дайджест, особенно аккуратно слить «домашку».

Промпт: см. `11_PROMPTS.md`. Версия промпта обязательна в meta (`prompt_version`).

### Stage 5 — Validate digest (лёгкий QA)

Автоматические проверки (не LLM):
- файл не пустой;
- есть секции по заголовкам (Тема / Тезисы / Домашка);
- если в транскрипте есть маркеры домашки (`домашн`, `задани`, `параграф`) — секция домашки не должна быть «не упоминалось» без причины (warning);
- длина дайджеста в разумных пределах (не 2 предложения и не простыня = транскрипт).

### Stage 6 — Deliver

CLI: путь к `.md` в консоли (флаг `--open` открывает файл).  
Веб: страница показывает дайджест и ссылки «Скачать .md / транскрипт» (сделано, ADR-0007).  
Позже: PDF export, Notion и т.д.

### Stage 7 — Metrics hook

Записать в `runs/{RUN_ID}/metrics.json`:
- timings per stage;
- sizes;
- (вручную позже) human scores.

## 3. Диаграмма последовательности (MVP0 CLI)

```text
User          CLI           Ingest        ASR           LLM          FS
 │             │              │            │             │            │
 │ run audio   │              │            │             │            │
 │────────────►│              │            │             │            │
 │             │ copy/normalize───────────►│             │            │
 │             │              │────────────┼─────────────┼───────────►│ audio/
 │             │ transcribe   │            │             │            │
 │             │──────────────────────────►│             │            │
 │             │              │            │─────────────┼───────────►│ transcripts/
 │             │ summarize    │            │             │            │
 │             │────────────────────────────────────────►│            │
 │             │              │            │             │───────────►│ digests/
 │             │◄─────────────────────────────────────────            │
 │◄── path.md  │              │            │             │            │
```

## 4. Состояния Run

```text
created → ingesting → asr_running → asr_done → summarizing → digest_ready → delivered
                 ↘ failed_* (с указанием stage)
```

Хранить `status` в `runs/{RUN_ID}/run.json`. Там же — `progress` (0..1) и
`progress_stage`; по ним веб-интерфейс рисует полосу прогресса в процентах.
Этап `analytic` выполняется после ASR, если включён в конфиге.

## 5. Политика повторных запусков

| Ситуация | Поведение |
|----------|-----------|
| Уже есть transcript, нет digest | Можно `--from summarize` |
| Плохой digest, тот же transcript | `--from summarize --force` |
| Плохой ASR | `--from asr --force` (дороже по времени) |
| Смена промпта | новый `prompt_version`, пересчёт digest |

## 6. Параллелизм

MVP0: строго последовательно, один run за раз.  
Реализовано: очередь с одним worker-потоком в веб-слое, чтобы не запускать два Whisper сразу.
