# ADR-0007: Веб-интерфейс вместо Telegram-бота

- Status: Accepted
- Date: 2026-09-28

## Context

По roadmap первый интерфейс доставки (MVP1, топология C) предполагался как Telegram-бот.
Владелец проекта от Telegram отказался и запросил веб-версию: страница, куда загружают
аудио урока, и где появляется готовый дайджест.

Пайплайн к этому моменту уже готов и работает end-to-end (ASR + GigaChat).

## Decision

Первым пользовательским интерфейсом делаем **локальное веб-приложение** поверх пайплайна:

- FastAPI + Uvicorn, один процесс;
- тяжёлая обработка (ASR/LLM) выполняется в фоне через очередь с **одним worker-потоком**
  (чтобы не запускать несколько Whisper одновременно);
- страница с формой загрузки, опросом статуса и показом дайджеста;
- запуск: `lessondigest serve` (по умолчанию только `127.0.0.1`; `--host 0.0.0.0` — доступ
  с телефона по Wi-Fi).

Telegram-бот исключается из roadmap.

## Consequences

+ Нет зависимости от сторонних платформ и токенов
+ Работает и с ноутбука, и с телефона в той же сети
+ Пайплайн не изменён — веб это тонкий слой (`web/jobs.py`, `web/app.py`, `web/page.py`)
− Авторизации нет: выставлять наружу без доработки нельзя (см. `06_SECURITY_PRIVACY.md`)
− Нужен постоянно запущенный процесс (ноутбук или VPS)
